## 0. 说明

本文档是本项目的**验收标准**,验收以本文档为准,**定稿于 2026-10-19**。所有条目都要实测通过,并留存证据(截图、接口响应、数据库记录或日志),才算验收通过。如需变更,要另出新版本并写明修订记录。

**适用范围**:系统导航共五项:**上 key(渠道管理)**、**账单**、**对账**、**用户管理(仅管理员)**、**设置**。「模型 / 对话 / 导出」三个页面已移除,不在验收范围内,但要验证这三个页面已经下线(见 0.2)。

### 0.1 用例标注约定

- `[正常]`:主流程、正常输入。
- `[边界]`:临界值、极限数据量、时间点边界。
- `[异常]`:非法输入、越权、上游故障、网络异常等。
- 用例编号格式:`模块-序号`,例如 `AUTH-01`。
- 每条用例都写明 **预期结果 / 判定标准**。达到判定标准才勾选 `- [x]`。

### 0.2 通用前置检查

- [ ] **GEN-01** `[正常]` 导航栏只有「上 key、账单、对账、用户管理、设置」五项。**预期**:不出现模型、对话、导出入口;供应商登录时也不出现「用户管理」。
- [ ] **GEN-02** `[异常]` 直接访问已移除页面的 URL(模型 / 对话 / 导出原路由)。**预期**:返回 404 或跳转首页,不渲染旧页面,也不报前端错误。
- [ ] **GEN-03** `[正常]` 验收环境的测试数据已准备好:至少 1 个管理员、2 个供应商(A、B)、每个供应商名下若干渠道、一套可调用的 New API 测试实例。**预期**:数据准备记录已存档。

## 1. 账号 / 角色权限

### 1.1 登录

- [ ] **AUTH-01** `[正常]` 管理员用正确的账号密码登录。**预期**:登录成功,进入首页,看到全部五项导航。
- [ ] **AUTH-02** `[正常]` 供应商用正确的账号密码登录。**预期**:登录成功,只看到「上 key、账单、对账、设置」,没有「用户管理」。
- [ ] **AUTH-03** `[异常]` 密码错误或账号不存在。**预期**:登录失败,提示统一写「账号或密码错误」,不透露账号是否存在。
- [ ] **AUTH-04** `[异常]` 账号或密码为空,或超长(例如 > 256 字符),或含特殊字符、SQL 注入串。**预期**:前端校验拦截或后端返回明确错误;不报 500,也不发生注入。
- [ ] **AUTH-05** `[边界]` 会话过期或手动登出后,访问任意业务页面或接口。**预期**:页面跳转登录页,接口返回 401;重新登录后能正常使用。
- [ ] **AUTH-06** `[异常]` 已禁用或已删除的账号尝试登录。**预期**:拒绝登录,并给出明确提示。

### 1.2 数据可见范围

- [ ] **AUTH-07** `[正常]` 管理员查看渠道列表、账单、对账。**预期**:能看到所有供应商的全部数据,条数与数据库一致。
- [ ] **AUTH-08** `[正常]` 供应商 A 查看渠道列表。**预期**:只显示 A 创建的渠道,条数与数据库中 `创建人 = A` 的记录数一致。
- [ ] **AUTH-09** `[正常]` 供应商 A 查看账单、对账。**预期**:只包含 A 名下渠道的数据;汇总金额只按 A 的渠道计算。
- [ ] **AUTH-10** `[正常]` 供应商 A 使用筛选、搜索、多 ID 粘贴搜索。**预期**:结果里不会出现 B 或管理员的渠道,即使输入了他人的渠道 ID。

### 1.3 越权拦截(重点)

- [ ] **AUTH-11** `[异常]` 供应商 A 改 URL 或接口参数,访问 B 的渠道详情、编辑页。**预期**:返回 403(或 404),页面不显示任何 B 的数据。
- [ ] **AUTH-12** `[异常]` 供应商 A 直接调用后端代理接口,对 B 的渠道执行编辑、启用、禁用、测试、删除。**预期**:全部被拦截(403),B 的渠道状态和数据库记录都没有变化。
- [ ] **AUTH-13** `[异常]` 供应商 A 调用账单、对账接口时,带上 B 的供应商 ID 或渠道 ID 参数。**预期**:返回 403,或只返回 A 自己的数据,不泄露 B 的金额。
- [ ] **AUTH-14** `[异常]` 供应商访问「用户管理」页面 URL 及其接口。**预期**:页面拦截,接口返回 403。
- [ ] **AUTH-15** `[异常]` 供应商在批量操作里混入他人的渠道 ID。**预期**:他人渠道全部被拒绝,并在结果汇总中列为失败(原因:无权限);本人渠道正常处理。
- [ ] **AUTH-16** `[异常]` 未登录时直接调用任意后端代理接口。**预期**:返回 401,不会转发到 New API 上游。
- [ ] **AUTH-17** `[异常]` 前端源码、接口响应、浏览器存储中都找不到 New API 管理令牌。**预期**:令牌只保存在后端,前端拿不到。

### 1.4 用户管理(仅管理员)

- [ ] **AUTH-18** `[正常]` 管理员新增、编辑、禁用用户,并指定角色(admin / vendor)。**预期**:操作成功;被禁用的用户立即无法登录,已有会话失效或下次请求时被拒。
- [ ] **AUTH-19** `[边界]` 新增用户时账号重复。**预期**:提示「账号已存在」,不创建重复记录。

### 1.5 操作日志

- [ ] **AUTH-20** `[正常]` 对渠道做新增、编辑、启用、禁用、测试、删除、批量操作。**预期**:每次操作都生成日志,内容包含**操作人、操作时间(北京时间)、渠道 ID / 名称、操作类型、变更前后的关键字段**。
- [ ] **AUTH-21** `[正常]` 批量操作 N 个渠道。**预期**:生成 N 条逐渠道日志(或 1 条批次日志加 N 条明细),能追溯到每个渠道。
- [ ] **AUTH-22** `[异常]` 操作失败,或因越权被拦截。**预期**:同样记录日志,并标明失败及原因。
- [ ] **AUTH-23** `[异常]` 供应商查看或篡改操作日志。**预期**:供应商最多只能看自己的操作日志,任何人都不能修改或删除日志。

## 2. 渠道管理(核心页)

> 字段、类型、表单、默认值、校验都与 New API 原版一致,类型清单(约 52 种)从源码的渠道类型常量中获取,不手写。交互参照 keyman 渠道管理;外观为 v2 浅色多彩风格。

### 2.1 字段与类型一致性

- [ ] **CH-01** `[正常]` 类型下拉清单与 New API 源码的渠道类型常量逐项比对。**预期**:类型数量、名称、常量值完全一致(约 52 种),没有缺失、多余或值错位。
- [ ] **CH-02** `[正常]` 逐个类型切换,检查表单字段。**预期**:每种类型显示的字段、必填项、占位提示、默认值都与原版一致。
- [ ] **CH-03** `[正常]` 高级项完整可用:优先级、权重、标签、状态码映射、模型重定向、测试模型、备注、自动禁用开关。**预期**:都能填写和保存,回显正确,写入上游后的值与输入一致。
- [ ] **CH-04** `[异常]` 状态码映射、模型重定向填入非法 JSON。**预期**:校验拦截并提示错误位置,不提交。
- [ ] **CH-05** `[边界]` 优先级、权重填 0、负数、小数、超大值、非数字。**预期**:校验规则和取值范围与原版一致,非法值被拦截。

### 2.2 一致性对拍(重点,一项不过即整体不过)

- [ ] **CH-06** `[正常]` 用同一组输入数据,在原版 New API 后台和本系统各建 1 个渠道,导出两边数据库里的渠道记录逐字段比对。**判定**:字段集合、字段值、默认值、类型常量值**完全一致**(只允许 ID、创建时间等自增或时间类字段不同);**少一个字段、多一个字段或任意一个默认值不同,都判定不通过**。
- [ ] **CH-07** `[正常]` 对每种渠道类型都执行 CH-06(至少覆盖全部类型的最小必填组合)。**预期**:所有类型的对拍全部通过,对拍结果表随验收报告提交。
- [ ] **CH-08** `[边界]` 对拍时把全部高级项都填满(优先级、权重、标签、状态码映射、模型重定向、测试模型、备注、自动禁用)。**预期**:两边记录一致。
- [ ] **CH-09** `[边界]` 对拍时高级项全部留空。**预期**:两边写入的默认值一致(包括空字符串、null、0 的差别)。

### 2.3 列表

- [ ] **CH-10** `[正常]` 列表列齐全:渠道ID、名称、类型、分组、消耗(今日之前 / 今日 / 累计)、成功率、状态、创建人、创建时间、操作。**预期**:列名与顺序符合设计,数据与库一致。
- [ ] **CH-11** `[正常]` 分页由服务端强制执行,每页 20 条。**预期**:接口每次最多返回 20 条;前端改 `pageSize` 参数也无效(服务端强制 20)。
- [ ] **CH-12** `[正常]` 消耗三列(今日之前 / 今日 / 累计)分别做升序、降序排序。**预期**:排序在服务端全量执行(不是只排当前页),跨页顺序正确。
- [ ] **CH-13** `[正常]` 类型列显示彩色标签加图标,不同类型颜色可区分。**预期**:与设计一致,无错配。
- [ ] **CH-14** `[正常]` 按类型筛选(单选或多选)。**预期**:结果只包含所选类型,总数正确,分页正常。
- [ ] **CH-15** `[边界]` 筛选结果为 0 条。**预期**:显示空状态,不报错。
- [ ] **CH-16** `[边界]` 最后一页不足 20 条,或页码超出范围。**预期**:正确显示剩余条数;超出范围时返回空页或回到最后一页,不报错。

### 2.4 大数据量(性能)

- [ ] **CH-17** `[边界]` 造数千个渠道(≥ 3000,已确认),打开列表首页。**预期**:首屏在可接受时间内加载完成(≤ 3s,已确认),不超时。

- [ ] **CH-19** `[边界]` 一次粘贴多个 ID 搜索(例如 100、500 个,用逗号、空格、换行混合分隔)。**预期**:正确解析,不超时;结果准确,不存在的 ID 会提示。
- [ ] **CH-20** `[异常]` 多 ID 搜索中混入非法字符、重复 ID、超长输入。**预期**:自动去重,并提示无效项;不报 500。
- [ ] **CH-21** `[边界]` 数千渠道下连续翻页、排序、筛选组合操作。**预期**:页面不卡,接口不超时,数据正确。

### 2.5 状态显示

## 3. 拉取限流

### 3.1 限流参数

- [ ] **RL-01** `[正常]` 单个网关每分钟最多发起 60 次上游请求。**预期**:按日志统计,任意 60 秒窗口内对同一网关的请求数 ≤ 60。
- [ ] **RL-02** `[正常]` 单个渠道每分钟最多 5 次。**预期**:任意 60 秒窗口内同一渠道的请求数 ≤ 5。
- [ ] **RL-03** `[正常]` 同时最多 3 个并发请求。**预期**:任意时刻进行中的请求数 ≤ 3。
- [ ] **RL-04** `[边界]` 瞬时提交远超上限的任务(例如 1000 个)。**预期**:**全部排队**按顺序执行,不报错、不丢任务,最终全部完成。

### 3.2 失败处理

- [ ] **RL-05** `[异常]` 上游返回 429 并带 `Retry-After`。**预期**:按 `Retry-After` 的时长等待后重试,不提前重试。
- [ ] **RL-06** `[异常]` 上游返回 429 但没有 `Retry-After`。**预期**:按指数退避处理。
- [ ] **RL-07** `[异常]` 请求连续失败(5xx 或超时)。**预期**:重试间隔按指数退避递增,有上限,并记录日志。
- [ ] **RL-08** `[异常]` 某个渠道连续失败超过阈值。**预期**:该渠道自动降频,恢复成功后频率回到正常。
- [ ] **RL-09** `[异常]` 上游整体不可用。**预期**:队列暂停或退避,不会刷爆上游;上游恢复后继续执行。

### 3.3 后台同步与缓存

- [ ] **RL-10** `[正常]` 后台每 5 分钟同步一次消耗和状态数据并存库(或按每日拉取任务执行)。**预期**:同步时间戳按周期更新。
- [ ] **RL-11** `[正常]` 页面读取渠道列表和消耗。**预期**:读的是本地缓存,**不实时请求上游**;可以通过抓包或日志验证。
- [ ] **RL-12** `[边界]` 某一轮同步还没结束,下一轮已经到期。**预期**:不并发重复执行,不重复计数。

### 3.4 压测

- [ ] **RL-13** `[边界]` 在数千渠道下运行完整的同步周期。**判定**:①不漏拉(拉到的渠道数 = 总渠道数,或差额都被标为未同步);②不重复计数(消耗合计与上游一致);③同步期间页面操作不卡。
- [ ] **RL-14** `[边界]` 同步中途重启服务。**预期**:能断点续拉,不重复计数。

## 4. 账单(定稿)

### 4.1 切日与发布

- [ ] **BILL-01** `[正常]` 按北京时间(UTC+8)每天 00:00 切日,统计前一天 00:00–24:00 的消耗。**预期**:账单日期和统计区间正确,与服务器所在时区无关。
- [ ] **BILL-02** `[正常]` 00:00 时后台开始限流排队拉取。**预期**:任务按时启动,并遵守第 3 章的限流规则。
- [ ] **BILL-03** `[正常]` 全部拉取完成后立即发布账单。**预期**:凌晨出结果,**最晚 06:00 一定发布**。
- [ ] **BILL-04** `[边界]` 拉取过程中服务中断、重启。**预期**:断点续拉,不重复拉取,也不重复计数。
- [ ] **BILL-05** `[边界]` 到 06:00 时仍有渠道没拉到。**预期**:按时发布,没拉到的渠道标「未同步」(见 4.4)。
- [ ] **BILL-06** `[正常]` 账单发布前访问账单页。**预期**:照常显示上一份完整账单;页头显示「汇总中 已完成 n/总数」和上次完成时间,n 随进度更新。
- [ ] **BILL-06a** `[正常]` 账单页页头注明「仅统计通过上号器添加的渠道」。**预期**:文案可见。
- [ ] **BILL-06b** `[异常]` 在 New API / KeyMan 后台直接建的渠道(不上号器)。**预期**:不出现在账单、圆环、对账中。
- [ ] **BILL-06c** `[异常]` 上号器建的渠道在 New API 后台被删后重建(ID 变了)。**预期**:新 ID 不算进账单;对账把「库里有、网关上找不到」的渠道单独列出提醒。

### 4.2 算法(重点)

- [ ] **BILL-07** `[正常]` 每个渠道记录 0 点基准值 = 0 点那一刻的「累计 − 今日」。**预期**:基准值来自 0 点切日口径,**不能用拉取时读到的累计值**。
- [ ] **BILL-08** `[正常]` 前一天消耗 = 今天的基准值 − 昨天的基准值。**预期**:与人工计算一致。
- [ ] **BILL-09** `[边界]` **不同时间点拉取用例**:同一渠道分别在 00:01、02:00、05:59 拉取,且这段时间里有新消耗。**预期**:三次算出的前一天消耗相同,**0 点之后的消耗不算进前一天**。
- [ ] **BILL-10** `[边界]` 重跑同一天的账单任务(一次或多次)。**预期**:结果不变,不重复计数。
- [ ] **BILL-11** `[边界]` 渠道当天没有消耗。**预期**:前一天消耗 = 0(真 0),与「未同步」区分显示。
- [ ] **BILL-12** `[异常]` 累计值变小(渠道删除后重建、额度被重置)。**预期**:能识别出来并标「异常」,不出现负消耗,也不计入正常汇总。
- [ ] **BILL-13** `[正常]` 渠道在上号器建好时立刻记一次累计当基准,从下一天起按「今日基准 − 昨日基准」正常算。**预期**:账单只统计上号器库里有记录的渠道。

### 4.3 未同步与补拉

- [ ] **BILL-14** `[异常]` 渠道没拉到数据。**预期**:标「未同步」,**不按 0 计算,不进圆环图**。
- [ ] **BILL-15** `[正常]` 后台持续补拉未同步渠道,补拉成功后。**预期**:自动并入当天账单,汇总和图表刷新,不重复计数。
- [ ] **BILL-16** `[边界]` 补拉拖过了下一个 0 点。**预期**:这两天合成一条「两日合计」记录,金额等于两日总消耗。

### 4.4 测试消耗

- [ ] **BILL-17** `[正常]` 测试渠道产生的消耗单独成列。**预期**:不计入供应商的正常消耗。
- [ ] **BILL-18** `[边界]` 如果 New API 自带的测试会计入 `used_quota` 或日志:按记录的测试次数扣减。**判定**:扣减后,正常消耗 + 测试消耗 = 上游累计增量,对账能对平。

### 4.5 权限与明细

- [ ] **BILL-19** `[正常]` 管理员看全部账单;供应商只看自己的。**预期**:与第 1 章权限一致。
- [ ] **BILL-20** `[正常]` 明细表分「今日之前 / 今日 / 累计」三列。**预期**:数值与渠道列表一致。
- [ ] **BILL-21** `[正常]` 按分组、类型、渠道分别汇总。**预期**:各维度合计相等,都等于总消耗(不含未同步部分)。

### 4.6 可视化

- [ ] **BILL-22** `[正常]` 主体为圆环图:总消耗居中,显示各渠道 / 供应商 / 类型的占比和剩余额度。**预期**:占比之和为 100%,数值与明细表一致。
- [ ] **BILL-23** `[正常]` 下方显示约 30 天的按天趋势线,再下方是明细表。**预期**:每天的数据点与历史账单一致。
- [ ] **BILL-24** `[边界]` 存在未同步渠道。**预期**:图例注明「含 n 个未同步渠道,未计入」,n 准确。
- [ ] **BILL-25** `[边界]` 历史数据不足 30 天,或全部为 0。**预期**:图表正常渲染,不报错。
- [ ] **BILL-26** `[正常]` 金额换算统一按 quota / 500000 = 美元。**预期**:页面显示金额与换算结果一致,保留位数统一。

## 5. 对账

### 5.1 自动执行与三项自检

- [ ] **REC-01** `[正常]` 账单发布后自动运行对账。**预期**:不需要手动触发,有执行记录。
- [ ] **REC-02** `[正常]` **①渠道自洽**:昨日 0 点累计 + 昨日消耗 = 今日 0 点累计。**预期**:相等时判定一致;不相等或累计变小时标「异常」。
- [ ] **REC-03** `[正常]` **②逐渠道核对**:把我方按基准算出的每渠道消耗与 `/api/log/stat`(`type=2`,按 channel + 前一天时间戳)逐渠道比对。**判定**:误差 ≤ 1% 为「一致」;超过标「有差异」;查不到日志标「日志缺失」。**不做网关总数核对**(网关含非上号器渠道,会误报)。
- [ ] **REC-04** `[边界]` 误差恰好为 1%、1.0001%、0.9999%。**预期**:边界判定与阈值规则一致(≤ 1% 为一致)。
- [ ] **REC-05** `[正常]` **③状态异常**:已禁用的渠道消耗仍在增长;已启用的渠道连续多天消耗为 0。**预期**:两种情况都被标出,并写明原因。
- [ ] **REC-06** `[正常]` `/api/log/stat` 调用的参数正确(type=2、channel、起止时间戳为北京时间前一天 00:00:00–23:59:59 对应的时间戳)。**预期**:抓包核对参数无误。

### 5.2 口径联调

- [ ] **REC-07** `[正常]` 用真实数据跑满一天,核对退款、失败重试是否只记在我方或网关日志其中一边。**预期**:输出口径差异说明,先对齐口径再确定阈值,没有因口径不一致造成的误报。

### 5.3 边界与异常

- [ ] **REC-08** `[边界]` 跨天补拉的渠道(标「两日合计」)。**预期**:不参与单日比对,只校验两日总额。
- [ ] **REC-09** `[边界]` 渠道被删除或禁用。**预期**:使用快照数据,前一天有消耗的渠道仍然出现在对账单里。
- [ ] **REC-10** `[边界]` 补拉完成后。**预期**:对账自动重跑并刷新结果,不重复计数。
- [ ] **REC-11** `[异常]` 上游查询返回 0 和查询超时要区分。**预期**:超时归入「未同步 / 日志缺失」,不归入「有差异」;真 0 按正常值比对。
- [ ] **REC-12** `[异常]` 计算差额占比时分母为 0(例如网关日志为 0 而我方不为 0,或两边都为 0)。**预期**:不崩溃、不出现 NaN 或 Infinity;两边都为 0 判定一致,单边为 0 按规则标出。

### 5.4 阈值与处理流程

- [ ] **REC-13** `[正常]` 管理员修改对账阈值。**预期**:保存后对后续对账生效;修改记录进入操作日志。
- [ ] **REC-14** `[异常]` 供应商尝试修改阈值。**预期**:被拦截(403)。
- [ ] **REC-15** `[边界]` 阈值填 0、负数、> 100%、非数字。**预期**:校验拦截。
- [ ] **REC-16** `[正常]` 供应商对自己的对账单「确认」或「提异议」并填写备注。**预期**:状态更新,管理员能看到。
- [ ] **REC-17** `[正常]` 管理员处理异议后结单。**预期**:状态变为已结单,全流程有记录。
- [ ] **REC-18** `[异常]` 供应商确认或提异议他人的对账单。**预期**:被拦截。

### 5.5 第二步:供应商按月对账

- [ ] **REC-19** `[正常]` 下载 CSV 模板。**预期**:模板的列定义清晰,并附示例。
- [ ] **REC-20** `[正常]` 上传按模板填写的 CSV,或手动填写金额。**预期**:解析成功;误差 ≤ 2% 自动通过。
- [ ] **REC-21** `[边界]` 误差超过 2%。**预期**:进入「待处理」;双方备注确认后锁定账期。
- [ ] **REC-22** `[异常]` CSV 格式错误、缺列、编码异常(GBK / UTF-8 BOM)、金额非数字、重复行。**预期**:给出明确报错(定位到行和列),不导入脏数据。
- [ ] **REC-23** `[边界]` 账期锁定后尝试直接修改。**预期**:不允许修改,只能追加调整记录,调整记录可追溯。
- [ ] **REC-24** `[正常]` 导出对账单 CSV。**预期**:导出内容与页面一致,Excel 打开中文不乱码;供应商只能导出自己的数据。

### 5.6 对账页可视化

- [ ] **REC-25** `[正常]` 页面顶部三个圆环:一致 / 有差异 / 未同步(或日志缺失)的占比。**预期**:三者合计为 100%,与列表计数一致。
- [ ] **REC-26** `[正常]` 下方是差异列表,点击某一行。**预期**:进入该渠道当天的明细,数据正确。
