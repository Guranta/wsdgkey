# ainow 供应商账号网关 验收清单 v0.7

适用：ainow（New API v1.0.0-rc.25-fix-116，魔改版，供应商账号模式）。
基于码农 2026-10-31 调研的差异清单。测试渠道统一用 `qa-` 前缀，测完禁用或删除。文档里不写任何密码或 token。

## 一、接入与登录（AUTH-V）
- [ ] **AUTH-V-01** 设置里能新增网关类型「供应商账号」，填站点地址、账号、密码；保存后连接测试成功。
- [ ] **AUTH-V-02** 密码加密存库：数据库、日志、接口返回、前端页面里都看不到明文。
- [ ] **AUTH-V-03** 账号或密码错误：保存时给出明确提示，不保存，不反复重试。
- [ ] **AUTH-V-04a** 新增网关只显示站点地址、账号、密码三项，保存前必须先测试连接；续期状态可见，续期失败时顶部出黄色提示。
- [ ] **AUTH-V-04b** 网关名默认 `ainow-seller`，可手动改，改后保存生效。
- [ ] **AUTH-V-04c** token 剩不到 60 秒时自动续期（可把时钟或过期时间调近来验证）。
- [ ] **AUTH-V-04** token 约 15 分钟过期后自动续期，页面操作不中断、不需要重新登录。
- [ ] **AUTH-V-05** 续期失败（session 失效）时自动用账号密码重新登录一次；仍失败则网关标为「连接异常」，不死循环。
- [ ] **AUTH-V-06** 登录频率受限：短时间内多次失败后停止尝试并报警，不把账号刷到被封。
- [ ] **AUTH-V-07** 站点开启验证码或 MFA 后：明确提示「需要人工处理」，不误判为密码错误。
- [ ] **AUTH-V-08** 修改账号密码后旧凭据立即失效，新凭据生效。

## 二、渠道列表与详情（CH-V）
- [ ] **CH-V-01** 账号下原有的 26 个渠道全部导入上号器，导入后数量、名称、状态、分组跟站点一致；重复导入不会产生重复记录。
- [ ] **CH-V-01a** 导入的渠道从导入后第一次 0 点快照开始计费，导入当天和之前的消耗不补算。
- [ ] **CH-V-01c** 导入不改渠道任何设置，已自动禁用的保持原状态；列表和账单里带灰色「已导入」标签。
- [ ] **CH-V-01d** 「导入」按钮可以重复点，已导入的跳过，点完汇总导入、跳过、失败的数量。
- [ ] **CH-V-01e** 原版网关的对账功能保持不变，不受这类网关改动影响。
- [ ] **CH-V-01b** 导入的渠道归属于这个供应商账号，其他供应商看不到。
- [ ] **CH-V-02** 状态正确：启用、手动禁用、自动禁用区分显示。
- [ ] **CH-V-03** 分组（4 个）和模型列表（590 个）能正常加载，模型选择不卡顿。

## 三、新增与编辑（CH-V）
- [ ] **CH-V-10** 新增渠道成功，站点后台能看到，字段一致。
- [ ] **CH-V-11** 抽屉里直接隐藏（不是置灰）供应商设不了的字段：参数覆盖、请求头覆盖、status_code_mapping、tag、auto_ban、优先级、权重。
- [ ] **CH-V-12** 批量粘贴多个 key：没有批量接口时逐个提交，结果汇总「成功 n / 失败 m」，失败的说明原因。
- [ ] **CH-V-13** base URL 保留输入框，下方有小字「仅限站点允许的地址」；被站点拒绝时，把站点返回的错误原样显示在输入框下方。
- [ ] **CH-V-14** 达到站点返回的 `max_channels` 上限时（实时读取，不写死）「添加」按钮置灰，提示「已达站点上限」；不出现半成功的脏数据。
- [ ] **CH-V-15** 编辑渠道只改允许的字段，保存后站点数据一致。
- [ ] **CH-V-16** 抽屉顶部有灰色说明「此网关为供应商账号，部分字段不可设置」。
- [ ] **CH-V-17** 批量添加、刷新 Codex、获取模型列表、查余额这几个按钮直接不显示（不是置灰）。

## 四、测试、启用、禁用（CH-V）
- [ ] **CH-V-20** 单个测试正常，返回结果和耗时。
- [ ] **CH-V-21** 同一渠道 10 分钟内只能测一次，冷却规则和原有网关一致。
- [ ] **CH-V-22** 启用、禁用生效，站点状态同步。
- [ ] **CH-V-23** 批量启用和禁用：逐个调用，结果汇总正确，单个失败不影响其他。
- [ ] **CH-V-24** token 恰好过期时执行操作：自动续期后成功，不报 401 给用户。

## 五、账单（BILL-V）
- [ ] **BILL-V-01** 每天 0 点（北京时间）给每个渠道的 used_quota 记快照。
- [ ] **BILL-V-02** 当天消耗 = 两次快照之差，换算按 quota / 500000 = 美元。
- [ ] **BILL-V-03** 渠道新建当天以创建时的 used_quota 为基线。
- [ ] **BILL-V-04** 0 点快照失败会自动重试；当天补不上就标「缺数据」，不按 0 算，也不用前后两天平均。
- [ ] **BILL-V-04a** 这类网关的账单行有「快照计费」标签。
- [ ] **BILL-V-05** 测试不计入 used_quota（老板确认），账单不扣测试消耗，也不再显示「含测试消耗待确认」。
- [ ] **BILL-V-06** 渠道被删后重建（ID 变化）要标出来，不把旧渠道的累计量算到新渠道。

## 六、对账（REC-V）
- [ ] **REC-V-01** 这类网关不做对账，对账入口直接显示账单（按 0 点快照算的每日消耗），不显示对账结果、「全部一致」或「日志缺失」。

## 七、隔离与安全（SEC-V）
- [ ] **SEC-V-01** 供应商 A、B 互相看不到对方的网关和渠道。
- [ ] **SEC-V-02** 前端和接口返回不暴露站点的登录 token、cookie 和 X-Auth-Session。
- [ ] **UI-V-01** 供应商账号网关新增的文案在中英文下都有翻译，没有缺词、没有露出 key 名、没有溢出。
- [ ] **SEC-V-03** 和原有管理员模式网关同时存在时，两种网关互不影响。
