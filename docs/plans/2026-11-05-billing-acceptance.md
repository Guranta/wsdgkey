### 码农已核实（写入用例前提，2026-11-05）

1. 供应商账号 **不能删除、不能手动禁用** 渠道 → UI 必须隐藏对应入口（不是置灰可点）。
2. 渠道级 `log/stat?channel=` **可作为对账辅助**；**日消耗权威口径仍是 `customer_billing`**；全站抽样 `used_quota` 恒为 0。
3. channel test / status 类写操作对本账号常返回 403 → 持续无权限则隐藏。

## 一、鉴权与续期（AUTH-S）

- [ ] **AUTH-S-01** 设置里可新增网关类型「供应商 JWT / EE」，填写站点地址、账号、密码；保存前必须先测试连接，成功后才可保存。
- [ ] **AUTH-S-02** 密码加密存库：数据库、日志、接口返回、前端页面均无明文。
- [ ] **AUTH-S-03** 账号或密码错误：明确提示，不保存，不短时间狂重试。
- [ ] **AUTH-S-04** 登录成功后持有约 900s 的 access token；页面操作在过期前可正常调用渠道接口。
- [ ] **AUTH-S-05** token 即将过期或已过期时自动 `refresh`；请求带同源 **Origin/Referer**（以及所需的 Authorization / X-Auth-Session），续期成功则用户无感。
- [ ] **AUTH-S-06** refresh 缺少 Origin/Referer 或同源校验失败时，上游返回类 `AUTH_ORIGIN_FORBIDDEN`：上号器不得死循环刷 refresh；应回退一次账密重登或标「连接异常」并提示。
- [ ] **AUTH-S-07** session 失效后自动重登一次仍失败 → 网关标「连接异常」，停止重试并告警，不把账号打封。
- [ ] **AUTH-S-08** 短时间多次登录失败有限频与明确提示。

## 二、渠道导入与权限 UI（CH-S）

- [ ] **CH-S-01** 一键导入本站约 601 个渠道：数量、名称、状态、分组与上游一致；分页拉取（page_size≤100）。
- [ ] **CH-S-02** 重复点击导入：已导入跳过，汇总「导入 / 跳过 / 失败」数量，不产生重复记录。
- [ ] **CH-S-03** 导入 **不改** 上游任何字段与状态（含已自动禁用的保持原样）；列表带灰色「已导入」标签。
- [ ] **CH-S-04** 导入过程遵守限流（建议每网关 ≤60/min、并发 ≤3），不导致大面积 429/超时把站打挂。
- [ ] **CH-S-05** **隐藏**「删除渠道」入口（供应商不可删）；页面与批量操作均不可触发删除 API。
- [ ] **CH-S-06** **隐藏**「手动禁用 / 启用」类入口（供应商不可手动禁用）；不得出现可点击的置灰按钮去调 status PUT。
- [ ] **CH-S-07** 若 channel test 持续 403 / 无权限：**隐藏**「测试」按钮，并说明「站点未开放」类文案；不得反复自动重试 test。
- [ ] **CH-S-08** 权限探测结果变化（例如日后开放）后，入口显示与探测一致；有权限才显示对应按钮。
- [ ] **CH-S-09** 列表只读展示 `status_reason`（如欠费、密钥重复）及 `customer_billing` 的 source / state / 汇率（只读）。
- [ ] **CH-S-10** `used_quota` 在本站恒为 0：渠道详情不得把它当作「今日消耗」展示权威数字。

## 三、计费源选择与兼容（SRC）

- [ ] **SRC-01** 网关类型 = 供应商 JWT / EE 时，计费源自动为 **C（customer_billing）**，不可误绑 A/B。
- [ ] **SRC-02** 网关类型 = ainow 供应商时，计费源为 **A（used_quota）**；账单行标签为快照计费（used_quota）。
- [ ] **SRC-03** 网关类型 = 管理员 Access Token 时，计费源为 **B（log/stat）**；渠道级对账能力保持。
- [ ] **SRC-04** 升级后，历史管理员网关账单、ainow 快照账单 **仍可正常打开与汇总**，金额与升级前抽样一致（回归）。
- [ ] **SRC-05** 本站日消耗权威为 `customer_billing`；渠道级 `log/stat?channel=` 若展示，仅作 **对账辅助**，不得覆盖 / 改写 C 算出的日消耗。
- [ ] **SRC-06** 账单行标明计费来源（点据金额 / 快照计费 / 日志计费），避免口径混淆。

## 四、假零与质量态（BILL-C · 假零）

> **铁律**：`missing` / `stale`（按产品定义不可信时）/ `unavailable` **禁止**在 UI 显示成「今天 $0」。只有权威源明确返回数值 0 且 quality=ok 时，才允许「今天 $0」。

- [ ] **BILL-C-01** `customer_billing.state=ready` 且 `amount_usd` 日差为 0（quality=ok）→ 账单该日显示 **$0**，并视为真实零消耗。
- [ ] **BILL-C-02** 快照拉取失败或当日无快照 → `quality=missing`：账单该日显示 **「缺数据 / 未同步」**，**不得**显示「今天 $0」，汇总与环形图不把该日当 0 计入。
- [ ] **BILL-C-03** `state=unavailable` → `quality=unavailable`：同上，显示不可用/缺数据文案，**禁止**假零。
- [ ] **BILL-C-04** `stale=true` 且仍出数：金额可显示但必须带 **「可能滞后」** 标记；若产品规定 stale 当日不计入环，则环形图排除且不得显示为 $0 扇区。
- [ ] **BILL-C-05** 环形图 / 日汇总：所有 `quality != ok`（及产品规定排除的 stale）**排除出金额环**；另有「未同步」计数或灰区，用户能区分「真零」与「没数」。
- [ ] **BILL-C-06** 导出 CSV：缺数据行 `amount` 为空或显式质量列，不写 `0` 冒充。
- [ ] **BILL-C-07** 相邻两日 ready 快照差值为 **负**：不得静默取绝对值当消耗；标异常/不可用并告警（与 amount_usd 是否累计的 TBD 相关，见文末）。

## 五、跨天快照（BILL-C · 跨天）

- [ ] **BILL-C-10** 每天 **00:00 Asia/Shanghai** 对已导入渠道打 `customer_billing` 快照（含 amount_usd / state / stale / as_of / rate）。
- [ ] **BILL-C-11** 0 点快照失败会自动重试；同日补成功可将 `missing` 更新为 `ok`，并留审计「补快照」。
- [ ] **BILL-C-12** 重试直至跨过当日仍失败 → 该北京日保持 **缺数据**，**禁止**用前后日平均或当作 0。
- [ ] **BILL-C-13** **跨日重试**：若首次成功快照落在次日 0 点之后才完成——不得把次日快照值写进「昨日」充数；昨日仍为缺数据，次日按次日规则计算；若产品有「两日合计」展示，须在 UI 明确标注为补算/合计且可追溯，默认账单仍按自然日分列。
- [ ] **BILL-C-14** 当日消耗 = 两次 **ready** 快照的 `amount_usd` 之差（在 TBD 确认累计口径成立的前提下）；任一侧非 ready → 当日非 ok。

## 六、导入当天基线（BILL-C · 导入）

- [ ] **BILL-C-20** 渠道导入成功后，**计费起点 = 导入之后的第一次 00:00 成功快照**；该快照为基线，本身不产生「导入前半日」消耗。
- [ ] **BILL-C-21** 导入当天 0 点前已产生的上游消耗 **不回填**、不估半日；账单从基线日→次日才出现第一笔日消耗。
- [ ] **BILL-C-22** 导入当日若尚未到达第一次 0 点：账单该渠道显示「未到计费起点 / 待首次快照」，**不是** $0。

## 七、对账入口（REC-S）

- [ ] **REC-S-01** 本站（源 C）对账入口 **关闭渠道级对账算法**，直接展示账单视图（与 ainow 一致），不出现「全部一致」类误导文案。
- [ ] **REC-S-02** 若产品提供渠道级 `log/stat?channel=` 辅助面板：标明「辅助，非日消耗权威」；其数字与 C 日消耗并存时，以 C 为准。
- [ ] **REC-S-03** 管理员网关（源 B）对账功能升级后 **回归通过**，不受 C/A 改动破坏。

---

## 八、规模与限流（SCALE）

- [ ] **SCALE-01** 601 渠道全量导入在限流下可完成，有进度或结果汇总，无长时间无响应假死。
- [ ] **SCALE-02** 日快照任务对 600+ 渠道分批（建议 ≤50/批）+ 队列，单渠道失败不阻断整批。
- [ ] **SCALE-03** 账单页默认聚合（分组/状态），明细懒加载；打开本站网关账单不白屏、不一次拉爆。
- [ ] **SCALE-04** 并发与 QPS 不超过约定上限；触发上游限流时有退避，不疯狂重试。

---

## 九、安全与隔离（SEC-S）

- [ ] **SEC-S-01** 前端、接口返回、浏览器存储不暴露站点 access token、cookie、X-Auth-Session。
- [ ] **SEC-S-02** 供应商 A/B 互相看不到对方网关与渠道；越权 ID 返回 403/404。
- [ ] **SEC-S-03** 与管理员网关、ainow 网关同屏共存互不影响。
- [ ] **SEC-S-04** 操作日志不落密码与 token；失败的权限调用有记录但不刷屏。
