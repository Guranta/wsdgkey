# 供应商 JWT 渠道页差异说明（给码农）

日期：2026-11-08（Asia/Shanghai）。对照：DESIGN v2.2 §9.1 / §9.6、计划 `docs/plans/2026-11-05-supplier-jwt-gateway.md`。  
老板当天下令：**JWT 全面适配 + 上 key（创建提前）+ 关键词搜索必过**；**鉴权走账密，不需要管理令牌**。

实现顺序（总监已定）：**① 搜索先上 → ② 放开创建（原 G8）→ owned 编辑/换 key 跟创建一起**。

## 0. 鉴权文案（老板补充 · 必改）

`newapi_supplier`（供应商 JWT）**永远不要出现 Access Token / 管理令牌输入或「请更新令牌」**。

| 场景 | 错误文案（现状易混） | 改为 |
| --- | --- | --- |
| 网关状态 pill | 「令牌失效」+ tooltip 提管理令牌 | 「需重新登录」（红）· tooltip「会话失效，请到设置 › 网关重新填写账号密码并测试连接」 |
| 顶部黄横幅 | 「令牌自动续期失败…当前令牌将于…」 | 「供应商 JWT 自动登录失败 · {网关} · {时间}（站点原文：{…}）。请到 设置 › 网关 重新填写**账号密码**并测试连接。」 |
| 设置抽屉 | 任何 Access Token / New-Api-User 字段 | **不渲染**（已有计划）；续期说明写「短时 JWT + 自动刷新；失败则用账密重新登录」 |
| 恢复路径 | 让用户贴新令牌 | **只**账密 → 测试连接 → 保存。刷新失败回落密码登录（线上已有），UI 与之一致 |

内部仍可存 JWT/refresh（服务端密文），前端与文案一律当「账密会话」，不叫令牌管理。

## 1. 渠道列表 · 关键词搜索（先上 · 必过）

对照 §9.1 chips；供应商 JWT 大列表（约 900+）当前「有输入但不好找」算缺陷。

### 1.1 布局（供应商 JWT 网关选中时强制）

筛选行最左（网关下拉右侧）放**显式搜索组**，不得缩进折叠里才露出：

1. **搜索输入框**（min-width 280）：保留 chips 行为  
   - placeholder：「渠道号 / 名称，可粘贴多个 ID（逗号、空格或换行分隔）」  
   - 纯数字（可带 `#`）→ ID chip；其余当关键字  
   - 300ms 防抖服务端检索；请求中右侧 14px spinner，旧结果保留  
2. **「搜索」按钮**（黑 stadium 小 pill 或 Secondary）：立即触发（防抖清零）  
3. **回车** = 立即搜（与按钮同效）  
4. 右侧仍可保留「n 个 ID」计数 pill  

本地已导入行：优先搜**本库**（名称 / upstream id / 备注）；需要命中上游未导入时再打 `GET /api/channel/search`（计划已写）。验收：「输入关键字 → 命中行出现在当前页结果」。

### 1.2 空态

| 场景 | 文案 |
| --- | --- |
| 有关键字无命中 | 「没有符合条件的渠道」+ 「重置筛选」 |
| 无渠道 | 「暂无渠道，点击「添加渠道」开始上 key」（创建放开后） |

### 1.3 非 JWT 网关

可继续用原折叠筛选里的 chips；**JWT 视图必须外露搜索框+按钮**，避免再「看不见」。

## 2. 上 key = 放开「添加渠道」（原 G8 提前）

### 2.1 列表按钮

| 项 | 规则 |
| --- | --- |
| 「添加渠道」 | **显示**（去掉 `supplierForbidden:create` / UI `hidden`） |
| 达上限 | 仅当站点返回 `max_channels` 且已达才 disabled + tooltip「已达站点上限」；**无该字段则永不出现上限文案** |
| 导入 | 仍显示「导入已有渠道」；与添加并列，导入不替代创建 |

### 2.2 创建抽屉（680px，对齐 §9.1.1，按 profile 裁剪）

- 顶灰说明：「此网关为供应商 JWT，部分字段与操作不可用。名称保存后可能带站点前缀。」
- **隐藏（不渲染）**：测试连接（行内/批量/抽屉三处全无）、删除、手动启停、自动封禁、优先级、权重、参数/头/状态码映射、标签、批量加钥模式、从上游拉模型、查余额、Codex——与计划 §6 一致；以 `editable_fields` + 实机拒绝为准，多藏不少露。
- **必留**（上 key 最小集）：类型/提供商、名称、**API 密钥**（单密钥）、模型（可手填）、分组（若 profile 有）、Base URL（hint「仅限站点允许的地址」；站点拒 → 红框 + 原文）、备注（若有）。
- 底栏：取消 · 黑「创建渠道」（**无**「测试连接」）。
- 提交：`POST /api/channel/`，`{mode:"single", channel}`；成功后列表应出现 `owned=true` 可管行；toast 可提「站点可能已加名称前缀」。
- 创建失败：展示站点原文，不吞错。

### 2.3 编辑 / 换 key（与创建同发）

| 行 | 「修改」 | 换 key |
| --- | --- | --- |
| `owned=true` | 显示；抽屉同创建裁剪；密钥可改（空=不改） | 同抽屉「凭证」 |
| `owned=false` | 隐藏；灰 pill「不可管」；操作「只读」 | 不可 |

可管为 0 时：空态「暂无可管理渠道 · 可通过「添加渠道」上 key」，**不算错误**（导入仅可见仍可搜、可计费）。

## 4. 验收对接（给测试）

必过增量：

1. JWT 网关设置无 Access Token 字段；会话失败横幅引导**账密重填**，不提管理令牌。  
2. 渠道页可见「搜索」框+按钮；关键字/ID 能命中已导入行。  
3. 「添加渠道」可见；创建成功得到可管行；密钥可在修改抽屉更新。  
4. `owned=false` 仍只读；无测试/删除/启停入口。
