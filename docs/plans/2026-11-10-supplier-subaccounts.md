# 总监需求定稿：供应商子账户（2026-11-10）

供其他 AI / 开发者以后实现。**本提交只交需求，不写业务代码，不加验收用例。**

## 背景

- 子账户建在**上号器自己的账号体系**（万事大吉 / 上号器）。父供应商在上号器里、在自己名下创建「子账户」。
- 子账户登录的是上号器，不是上游 JWT 供应商站。
- 今天上号器用户只有 `admin` 和 `supplier`。管理员可以 `createSupplier`（`lib/users.ts`；角色见 `lib/types.ts`）。没有子账户树。
- 子账户在父供应商**已经配好的网关范围**里操作，继承父的网关、渠道和账单视图。不发给子账户自己的网关凭据，也不让子账户去管网关。

## 已作废

更早锁定的「通过上号器在上游 JWT 站创建子账户」**作废**。实探当前供应商 JWT 站：供应商 role=5 没有子账户接口，`/api/user/` 返回 403。因此本需求只做上号器本地账号，不接上游建用户。

## 总监拍板

1. 子账户**可以**上 key / 换密钥（创建与替换密钥）。仍然只针对 `owned=true` 的行。导入行保持只读，与父供应商相同。
2. v1 **不**分配渠道。子账户看见父供应商名下的**全部**渠道（含导入行；导入行仍只读）。空态和列表规则跟当前网关规则。
3. 不能再建下一层子账户（没有下一级）。
4. 不能管理网关：不能创建、编辑、停用、删除网关；不能看见其他供应商的网关或账号。
5. 不能看见其他供应商的数据。
6. 账单**只读**，范围与父供应商相同。
7. 父供应商可以创建子账户、停用子账户、重置子账户密码。

## 未拍板

下面这些不在锁定里。实现时不要当成已决定：

- 上号器 admin 能否也管理子账户（创建 / 停用 / 重置密码）
- 命名规则（用户名、显示名）
- MFA
- 停用之后能否重新启用；能否删除子账户（已锁定的只有创建、停用、重置密码）
- 子账户能否自己改密码
- 子账户上的 key 记在父账号还是子账号名下
- 对账页是否对子账户开放
- 子账户数量上限
