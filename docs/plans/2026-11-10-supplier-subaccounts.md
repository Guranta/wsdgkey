# 总监需求定稿：供应商子账户（2026-11-10）

供其他 AI / 开发者以后实现。**本提交只交需求与设计差异，不写业务代码，不加验收用例。**

界面、权限和文案以 [`2026-11-10-supplier-subaccounts-diff.md`](./2026-11-10-supplier-subaccounts-diff.md) 为准。

## 背景

- 子账户建在**上号器自己的账号体系**（万事大吉 / 上号器）。父供应商在上号器里、在自己名下创建「子账户」。
- 子账户登录的是上号器，不是上游 JWT 供应商站。
- 今天上号器用户只有 `admin` 和 `supplier`。管理员可以 `createSupplier`（`lib/users.ts`；角色见 `lib/types.ts`）。没有子账户树。
- 子账户在父供应商**已经配好的网关范围**里操作，继承父的网关、渠道和账单视图。不发给子账户自己的网关凭据，也不让子账户去管网关。

## 已作废

更早锁定的「去 JWT 站建号」（通过上号器在上游 JWT 站创建子账户）**作废**。上游 role=5 没有子账户能力，核对写在设计差异的「附录 · 上游核对」。那条路径**不采用**。本需求只做上号器本地账号，不接上游建用户。

## 总监拍板

1. 子账户**可以**上 key / 换密钥（创建与替换密钥）。仍然只针对 `owned=true` 的行。导入行保持只读，与父供应商相同。
2. v1 **不**分配渠道。子账户看见父供应商名下的**全部**渠道（含导入行；导入行仍只读）。空态和列表规则跟当前网关规则。
3. 不能再建下一层子账户（没有下一级）。
4. 不能管理网关：不能创建、编辑、停用、删除网关；不能看见其他供应商的网关或账号。
5. 不能看见其他供应商的数据。
6. 账单**只读**，范围与父供应商相同。
7. 父供应商可以创建子账户、停用子账户、重置子账户密码。
8. Admin 可以看见全部子账户，并可以代父供应商创建、停用、重置密码。
9. v1 不能把子账户改挂到别的供应商。

## 未拍板

下面这些设计差异没有定。实现时不要当成已决定：

- MFA
- 能否删除子账户
- 子账户数量上限

## 设计差异

详见 [`2026-11-10-supplier-subaccounts-diff.md`](./2026-11-10-supplier-subaccounts-diff.md)。其中已经写明、此处不再标未拍板的还有：停用后可启用；子账户在设置里改自己的密码；子账户创建的 `owned=true` 渠道归属父供应商（父与子都看得见、都能管）；对账只读，范围同父。

## 非目标

- 本提交不实现、不改配置、不加验收用例（验收由测试在本文合并后另补）
- 不接上游建用户（附录不采用）
- v1 不把渠道划给个别子账户，不把子账户转到别的供应商
- 不给子账户单独的网关凭据
